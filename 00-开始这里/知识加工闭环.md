# 知识加工闭环

> 减肥不是把知识库变薄，而是把成长路径变清楚。资料不能只保存，必须经过加工，最后变成观点、知识点和输出。

## 一句话理解

知识库真正的核心不是分类，而是这条成长链：

```text
资料 → 总结 → 分析 → 洞察 → 提炼 → 观点/知识点 → 输出 → 复盘 → 再迭代
```

## 每一层是什么意思

### 1. 资料

原始输入，还不是知识。

来源可以是：

- flomo
- 抖音收藏/喜欢
- 仓库同步
- 网页文章
- 自己想法
- AI 对话
- 项目数据

入口：[[01-收件箱/收件箱说明]] / [[30-资料池/资料池总览]]

### 2. 总结

先用普通话说清楚：

> 这条资料到底在说什么？

总结不需要深刻，只要准确。

### 3. 分析

拆结构，问：

- 它解决什么问题？
- 它用了什么逻辑？
- 它为什么吸引人？
- 它适合谁？
- 它有什么边界？

### 4. 洞察

从资料背后看见更深一层：

- 用户真正想要什么？
- 我为什么会被它吸引？
- 这个内容能迁移到哪里？
- 它暴露了什么需求、习惯、动机？

洞察是知识库最有价值的地方。

### 5. 提炼

把洞察压成可复用的东西：

- 一句话观点
- 一个知识点
- 一个判断标准
- 一个话术结构
- 一个选题公式
- 一个项目动作

### 6. 观点 / 知识点

观点是可以表达的判断。  
知识点是可以复用的理解。

例子：

- 观点：直播话术不能把内部策划语直接说给用户听。
- 知识点：用户停留通常来自感觉、有用、故事、共鸣、信任。

### 7. 输出

观点和知识点必须变成输出：

- 短视频选题
- 直播话术
- 金句
- 文章
- 项目动作
- 复盘结论

入口：[[40-作品/作品总览]] / [[项目管理/项目管理总览]]

### 8. 复盘

输出后反过来修正知识：

- 哪句话有效？
- 哪个方向被用户否定？
- 哪个钩子留住人？
- 哪个判断错了？
- 下次怎么改？

复盘不是最后一步，而是下一轮资料。

## 最小版本

如果每天只做 10 分钟，就不要全做，只做这个：

```text
资料 → 总结一句话 → 提炼一个观点 → 形成一个小输出
```

## 完整版本

如果有 30-60 分钟，再做完整链：

```text
资料
→ 总结：它说了什么
→ 分析：它怎么成立
→ 洞察：它背后是什么需求/动机
→ 提炼：压成观点/知识点
→ 输出：变成话术/选题/项目动作
→ 复盘：看结果，修正规则
```

## 关键原则

- 分类是外壳，加工才是核心。
- 总结让资料变清楚。
- 分析让资料变有结构。
- 洞察让资料和人、项目、动机连接。
- 提炼让内容可复用。
- 观点和知识点让知识能表达。
- 复盘让知识能成长。
